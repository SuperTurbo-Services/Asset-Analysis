# SuperTurbo Macro Workspace — brand spec

Verified against the current repository and public dashboard on 2026-09-01.

## Existing brand assets

- The macro dashboard has no dedicated image logo or illustration asset in `public/`; its identity is typographic.
- Product name: `SuperTurbo` / `Macro Impact Dashboard`.
- Existing visual language: warm paper ground, white surfaces, ink-like text, restrained navy accent, and semantic green/amber/red.
- Existing font stack: system sans for body, Noto Serif SC/Georgia/Songti for editorial headings, and IBM Plex Mono/system mono for measurements.

## Existing palette anchors

- Ground: `#FBFAF8`
- Surface: `#FFFFFF`
- Sunk surface: `#F4F2EE`
- Ink: `#191713`
- Secondary ink: `#4A453D`
- Muted: `#7C7568`
- Structural accent: `#1E3A5F`
- Positive: `#1B7A52`
- Caution: `#96660F`
- Negative: `#AE3540`
- Legacy product accent: `#FF2442`, reserved for tiny brand moments rather than data semantics.

## Color derivation

- Sample: use the existing navy and warm paper as the product's strongest established anchors.
- Converge: each direction may use at most three chromatic accents plus one neutral scale. Positive/negative colors stay semantic and are never used as decoration.
- Rationale: warm paper preserves the product's research-publication character; navy communicates analytical structure without collapsing into generic technology blue.

## Direction-specific permissions

- Direction A may strip the palette to paper, ink, link blue, and semantic status colors to match Functional Brutalism.
- Direction B may deepen the existing navy and add a low-chroma mineral green for total-view/allocation emphasis.
- Direction C may add a narrow cyan-to-coral data ribbon derived from the existing navy and brand red, but never use a full-page purple gradient.

## Typography and component rules

- Body copy is at least 14px; compact labels are at least 12px.
- Numeric values use tabular figures and a mono or tightly spaced sans face.
- Serif is allowed only for high-level editorial framing, never for dense tables or controls.
- Range sliders must show the exact value and unit beside the control.
- Cards should be created by data hierarchy, not by wrapping every paragraph in a rounded rectangle.
- Icons must be line icons, simple geometric marks, or text labels; do not use decorative emoji.
- Source timestamps, evidence links, scenario assumptions, and the research disclaimer remain visible or one click away.

## Brand asset validation result

- No logo regeneration is needed because no source logo asset exists for this surface.
- No external product screenshots or competitor logos will be embedded.
- All three prototypes use the same textual SuperTurbo mark and real product vocabulary.
